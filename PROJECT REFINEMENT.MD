🧩 CMS Project Request Workflow (Refined)
1. Client Request Stage

Action: Client submits a Project Request Form via the CMS.

Data Captured:

Project title, description, category

Desired timeline

Estimated budget (optional)

Contact information

Preferred communication method (Email, Phone, etc.)
and other form (please look at our get started form!)

System Status: REQUEST_SUBMITTED

2. Admin Review & Off-Platform Negotiation

Action: Admin receives the new request and reviews its details.

Communication: Negotiation, clarification, and quotation happen off-platform (via client’s preferred channel).

Outcome: Agreement on project scope, deliverables, and final budget.

💡 Off-platform communication is acceptable and maintained for negotiation convenience.

3. Request Approval & Payment Setup

Action: Once agreement is finalized:

Admin approves the request in the CMS.

Admin sets/updates the final approved budget.

System changes request status to:
PENDING_PAYMENT

Client now sees the approved project request along with payment details in their dashboard.

Client View:
Shows payment instructions, total amount, due date, and payment methods.

4. Client Payment Confirmation

Action: Client pays the required amount via the displayed payment method.

System Updates:

Once payment is verified, the request status becomes:
PAID

Admin users can view the payment confirmation.

5. Task Creation and Assignment

Action: Admin creates tasks under the approved, paid project.
Each task includes:

Task title and description

Assigned adiutor (staff member)

Task-specific budget allocation

Deadline / milestones

Budget Control:
The system tracks and validates:

Total task budget ≤ project budget

Displays remaining balance or deficiency if exceeded.

6. Project Tracking & Updates

Admin View: Can monitor:

Each task’s progress

Budget utilization

Assigned adiutors

Project overall progress

Client View:
Can see:
Overall project progress + status

Notifications for updates or completion happens via email


7. Completion & Closing

Action: When all tasks are completed:

Admin marks project as Completed.

Client is notified and can review deliverables.

Optional:
Feedback or rating mechanism for project quality.
